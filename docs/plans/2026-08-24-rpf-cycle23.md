## Phase 1 — make Camera2 close terminality callback-authenticated

- [ ] **P1 / AGG23-01:** introduce an exact-device close owner that is armed before
  `CameraDevice.close()` and publishes `STRICTLY_RELEASED` only when
  `StateCallback.onClosed(expectedDevice)` arrives. Wrong-device, duplicate, and late callbacks must
  be inert; a bounded absent callback must retain the existing one-way process quarantine.
- [ ] Treat the exact device callback as sufficient for session ownership while preserving
  best-effort session/reader/image cleanup, callback invalidation, normal idempotent close, bounded
  caller latency, and every Engine replacement refusal door. A method return must never authorize
  acquisition.
- [ ] Add a narrow injectable/callback orchestration seam and deterministic tests where device close
  returns immediately but `onClosed` is delayed, duplicated, wrong-identity, absent, or racing close.
  Assert replacement admission remains closed until exact callback proof.

Acceptance: no CameraEngine path may acquire/start a replacement Camera2 graph before the exact old
device reports closed; timeout remains fail-closed.

## Phase 2 — own failed-open handles and remove camera-handler self-wait

- [ ] **P2 / AGG23-02:** claim every callback-supplied `CameraDevice` identity before observer or
  recovery effects. `onError`/`onDisconnected` before `onOpened` must close that exact handle once and
  route its `onClosed` through the terminal owner without double-close in late/intentional-close races.
- [ ] **P3 / AGG23-03:** split teardown initiation from terminal waiting, or return a terminal handle
  whose wait is consumed only on non-camera lanes. A callback on the camera HandlerThread must never
  block on work queued behind itself and must not manufacture quarantine from handler ordering.
- [ ] Add production-seam tests for error-before-open, disconnect-before-open, late-after-close,
  concurrent close callers, posted teardown ahead/behind an admitted callback, post failure, cleanup
  exception, timeout, and Engine replacement refusal/authorization.
- [ ] **AGG23-09:** correct the cycle-22 plan's completion evidence to describe the old pure terminal
  coverage accurately, then record the new CameraController/Engine orchestration evidence separately.

Acceptance: every platform-supplied device has exactly one retirement owner, and no camera-handler
callback can wait for its own queue or falsely quarantine the process.

  sibling lane is terminal.
- [ ] Require explicit marker retirement to observe no producer lease, no registered publication

Acceptance: once Delete wins, no old or process-owned lane can publish a future sibling or resurrect
the family in Gallery, including before that sibling has created a row or publication claim.
