## Phase 1 — isolate capture-family retirement by exact family

- [ ] **P1 / AGG21-01:** replace the process-global monitor-spanning family retirement transaction
  with an exact-family or bounded-stripe ownership protocol. Provider absence queries and retry
  sleeps must run outside the global preference/capacity monitor.
- [ ] Preserve same-family ordering: retirement may remove only the marker version it observed;
  deletion re-marking while an old absence query is in flight must survive. Preserve the 64-marker
  process-wide capacity contract without races or silent eviction.
- [ ] Add deterministic tests for blocked family A with durable mark progress for family B, and for
  same-family mark-before-retire, retire-before-re-mark, provider-present, query-failure, and commit-
  failure outcomes.
- [ ] Update `docs/ARCHITECTURE.md` to describe exact-family synchronization and the rule that no
  provider call or sleep runs under the global family metadata monitor.

Acceptance: one non-returning family absence query cannot delay durable deletion authority for an
unrelated family, and stale retirement can never erase newer deletion intent for the same family.
