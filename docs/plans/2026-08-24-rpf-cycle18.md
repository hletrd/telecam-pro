## Phase 1 — correct review deadline ownership and user-visible terminal states

- [ ] **P1 / AGG18-02:** replace the post-timeout `isCompleted` snapshot in
  `ProgressiveLatestWorkLane` with one atomic terminal operation that either claims an already
  produced completion or wins retirement and exact disposal of any racing late result. Clear the
  latest owner on every terminal and never manufacture `Retired` from an ambiguous nullable await.
- [ ] **P2 / AGG18-03:** record whether each request actually entered its blocking `work`. Return a
  distinct retryable active-timeout outcome when a started call exceeds the deadline; reserve
  capacity-exhausted/restart-required for a request that could not start because both lane consumers
  and the shared finite process pool are poisoned.
- [ ] Map active timeout to a localized review error with Retry in full-screen review and truthful
  non-sticky thumbnail behavior. Preserve restart guidance only for real acquisition exhaustion.
- [ ] Add deterministic tests for completion exactly at the timeout/classification boundary, exact
  publish-or-dispose ownership, `latest` clearing, a single slow active call with spare capacity,
  one blocked consumer plus a healthy replacement, and total lane/process saturation.

Acceptance: a current review request always reaches Completed, Retired by a real superseding owner,
retryable TimedOut, or genuine CapacityExhausted; no bitmap/player/surface is stranded and no active
call with spare capacity tells the operator to restart.
