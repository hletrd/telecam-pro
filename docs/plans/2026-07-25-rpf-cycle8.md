## 1. Slice order and rationale

Item 2 lands FIRST: it defines the preview-exposure environment that item 1's ZSL admission and
item 3's feedback cadence live in. Item 3 next (pure logic). Item 1's device spike runs as soon as
team-lead clears device time (it gates the ring design); the ring lands after 2+3. Item 4 is
independent and can interleave.

### S1 — Preview fluidity cap + residual digital gain derivation (item 2, wire side) — P1

- New `PREVIEW_FLUIDITY_MAX_EXPOSURE_NS = 66_666_667L` (1/15 s) in `ManualControls.kt`.
  Justification: 1/15 s is the slowest cadence that still reads as a live viewfinder (motion
  followable, AF/pan usable); it bounds dark-scene pipeline lag to ~0.53 s (8 × 66.7 ms) vs ~4 s
  at the 500 ms cap; and the brightness shortfall vs the old cap (500/66.7 ≈ 7.5×) fits inside the
  ≤16× gain bound with margin. The 500 ms `PREVIEW_SAFE_MAX_EXPOSURE_NS` clamp REMAINS as the
  outer safety invariant (the fluidity cap is strictly tighter — the wedge protection gets
  stronger, never weaker).
- Extend `previewExposureTrade` to cap at the fluidity ceiling (ISO trade logic unchanged, tighter
  cap) and return the **residual linear shortfall** after ISO headroom is exhausted:
  `gain = (wantNs × wantIso) / (appliedNs × appliedIso)`, clamped to `[1, 16]` (4 stops,
  `PREVIEW_MAX_DIGITAL_GAIN`). Beyond 16× the preview honestly darkens — same honest tail as
  today, four stops later. Return type becomes a small data class; `ExposureMathTest` pins the
  destructured pair today and is updated in the same commit.
- PROGRAM keeps its 1/30 s neutral target (mandate: unchanged); stills never pass
  `previewExposureCap` and are untouched. HAL-AE modes (video-P, flash-P) never enter the
  `manualAe` branch → no cap, no gain, by construction.
- Publication: the gain computed at the seam is surfaced from the controller after every preview
  submit (full rebuild AND fast path) via a `onPreviewDigitalGain` forwarding, change-gated with
  per-rebuild reset — the exact `onZoomResult→gl.setHalZoom` pattern — and re-seeded in the
  `gl.start` callback from the engine's cached value (GlPipeline drops posts before start).
- Tests: `ExposureMathTest` — cap value, ISO-first trading order, gain floor/ceiling, PROGRAM
  neutral target retained, still path unaffected, gain==1 whenever exposure fits the cap.
- Exit: unit green. (No visible change yet — GL consumes the gain in S2.)

### S2 — GL digital gain + honest meter/scopes semantics (item 2, render side) — P1

- `gl/Shaders.kt`: new `uDigitalGain` uniform, multiplied in **linear light immediately after the
  BT.1886 decode and before everything else** (gamut matrix, OETF/HLG/log transfer), in the
  PREVIEW draw only. Because `vec3 meter = base;` (:180) derives after that point, zebra and
  false-color automatically read the BOOSTED signal — **decided and documented: the meter
  simulates the true still exposure** (the still captures the uncapped exposure, so boosted
  zebra/false-color is the honest capture-judgment signal; A2 seam text untouched).
- The ANALYSIS/readback draw NEVER applies `uDigitalGain`: the AE loop must meter true sensor
  luma or it would double-count the boost and stop raising ISO (`analysisReadbackTransfer`
  discipline). Scopes (histogram/waveform), built CPU-side from the same unboosted readback,
  apply the gain via a 256-entry decode→gain→re-encode LUT before binning so they match the
  displayed/simulated story — AE alone consumes sensor truth. Pure, host-tested.
- Encoder draws: not applicable (boost exists only in AE-OFF *photo* preview; video-P is HAL-AE),
  but the uniform is explicitly forced to 1.0 on the encoder/analysis draw paths so no future
  route can leak it into a file.
- Plumbing: `GlPipeline.setPreviewDigitalGain(f)` → `FlipRenderer`, per-generation default 1.0.
- Tests: shader-structure tests (LogProfilesTest/ShaderTransferCodeTest style) pin the uniform's
  position (post-decode/pre-gamut, preview-only); LUT math test; forwarding change-gate test.
- Exit: unit green; device (dark desk scene, via team-lead): S/M at a multi-second want-exposure
  shows a fluid ≥15 fps preview at simulated brightness; zebra tracks the boosted signal; a
  captured still's EXIF shows the true uncapped exposure; screenshot + logcat evidence.

### S3 — AE error-proportional step schedule + cadence (item 3) — P1

- `AutoExposure.correctionStops`: replace the fixed ±0.30 clamp with an error-scheduled clamp
  `maxStep(|err|) = clamp(0.5·|err|, 0.30, 1.20)` — identical behavior to today for errors
  ≤ 0.6 stop (no regression on the tuned smoothness the comments defend), up to 1.2-stop ticks for
  a lens-cap/window scene change (a 5-stop error converges in ~4 ticks instead of ~17), damped
  proportional approach + existing deadband near target (no oscillation/breathing). The
  pitch-black branch returns the far cap. `driveProgram`'s ±0.35 shutter re-centering stays.
- Cadence: the meter remains every-5th-frame; item 2's fluidity cap raises the dark-scene floor
  to ~3 Hz (from 0.4 Hz), which is where the schedule's larger steps matter. No readback-rate
  change this cycle (readback cost is per-frame GL work; revisit only with device evidence).
- Tests: extend `AutoExposureTest` — schedule shape (continuity at both knees), convergence-time
  property (from ±5 stops, ≤ N ticks into deadband, no overshoot beyond deadband), driveProgram
  overflow paths under the schedule, EV-comp interaction.
- Exit: unit green; device (dark desk ↔ lit scene flip): converges visibly faster, no breathing at
  rest; logcat AE tick trace evidence.

- Admission predicate (pure, host-tested — `zslAdmissible(entry, intendedStill, now)`): serve a

### S5 — Macro too-close OSD + closer-lens hint (item 4) — P2

- Exit: unit green; device: macro subject inside min distance on TELE shows the tag and hint;

## 2. Cross-item interactions (design-locked)

- S1's cap **widens** preview↔still divergence in low light — exactly when S4's admission must
  refuse. The admission predicate compares actual vs intended sensor values, so this composes
  without special-casing.
- S3's larger steps ride S1's faster dark-scene meter cadence; both are required for the "AE feels
  fast in the dark" outcome.
- The GL gain never enters encoder/analysis draws, so S2 cannot contaminate video files, scopes'
  AE feed, or S4's ring frames (ring frames are camera-stream YUV, pre-GL by definition).
