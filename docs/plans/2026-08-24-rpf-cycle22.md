- [x] **P1 / AGG22-01:** make `CameraController.close()` publish an explicit strict-release result
  rather than returning `Unit` after an unchecked 1.5-second join. The result must distinguish

  concurrent close callers.
- [x] Teach every `CameraEngine` controller-replacement and terminal-close path to consume that
  result. A timed-out old graph must never authorize a same-process replacement session or camera
  acquisition; late teardown callbacks must remain inert and must not race a new topology.
- [x] Preserve off-main shutdown, bounded caller latency, dual-open fallback behavior, terminal
  acquisition gates, and normal close performance. Do not block the UI thread indefinitely or add
  speculative HAL retries.
- [x] Add deterministic handler-latch tests for strict completion, timeout ownership, concurrent
  close identity, and reconfiguration refusal after timeout. Reconcile `docs/ARCHITECTURE.md` with
  the explicit Camera2 release/quarantine boundary.

Acceptance: elapsed time alone can never be interpreted as Camera2 ownership release, and a stalled
old controller cannot overlap a replacement session.

- [x] Keep provider publication and its saved callback inside the exact-family authority, so a

Acceptance: once capture-family Delete wins, no old Engine can make a sibling Gallery-visible or
