## Phase 1 — require terminal Camera2 teardown ownership before replacement acquisition

- [ ] **P1 / AGG22-01:** make `CameraController.close()` publish an explicit strict-release result
  rather than returning `Unit` after an unchecked 1.5-second join. The result must distinguish
  teardown completed from an identity-owned timeout/quarantine outcome and remain idempotent across
  concurrent close callers.
- [ ] Teach every `CameraEngine` controller-replacement and terminal-close path to consume that
  result. A timed-out old graph must never authorize a same-process replacement session or camera
  acquisition; late teardown callbacks must remain inert and must not race a new topology.
- [ ] Preserve off-main shutdown, bounded caller latency, dual-open fallback behavior, terminal
  acquisition gates, and normal close performance. Do not block the UI thread indefinitely or add
  speculative HAL retries.
- [ ] Add deterministic handler-latch tests for strict completion, timeout ownership, concurrent
  close identity, and reconfiguration refusal after timeout. Reconcile `docs/ARCHITECTURE.md` with
  the explicit Camera2 release/quarantine boundary.

Acceptance: elapsed time alone can never be interpreted as Camera2 ownership release, and a stalled
old controller cannot overlap a replacement session.

## Phase 2 — serialize family deletion with cross-Engine still publication

- [ ] **P2 / AGG22-02:** introduce one exact-family publication authority shared by durable family
  mark, retirement, and the publication decision. The authoritative family-live check and provider
  `IS_PENDING=0` publication must be ordered against deletion across Engine instances.
- [ ] Keep unrelated families independent and keep global family metadata/capacity locks free of
  provider calls and retry sleeps. Preserve current same-Engine tombstones, process-surviving tails,
  recovery vetoes, exact-URI DISCARD fallback, and one-owner saved/review callbacks.
- [ ] If publication itself cannot safely remain inside the exact-family authority, add an
  authoritative post-publication family recheck whose losing path durably claims exact-URI DISCARD
  and deletes the row without emitting a saved callback.
- [ ] Add deterministic two-Engine tests for check → family mark/delete → publish, publication-first
  ordering, marker-retirement interaction, discard failure, and unrelated-family progress. Update
  `docs/ARCHITECTURE.md` with the cross-Engine publication/delete ordering contract.

Acceptance: once capture-family Delete wins, no old Engine can make a sibling Gallery-visible or
emit it as saved; a publication that wins first remains deletable by the ordered family operation.
