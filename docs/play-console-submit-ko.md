# Google Play 등록 안내 (한국어) — TeleCam Pro

Play Console에 직접 입력해야 하는 항목들의 한국어 작업 순서입니다.

**중요 — 이 문서는 값을 보관하지 않습니다.** 붙여넣을 실제 문자열(짧은 설명, 전체 설명, 출시
노트, 권한 사유)과 아티팩트 해시는 각각 `docs/play-store-listing.md`,
`docs/play-data-safety.md`, `docs/play-console-submit.md`에만 있습니다. 여기에 복사해 두면 그쪽이
바뀔 때 조용히 어긋나고, 실제로 이 저장소에서 그 방식으로 잘못된 값이 업로드 직전까지 간 적이
있습니다. 이 문서는 **어디서 무엇을 가져와 어디에 넣는지**만 알려줍니다.

스토어 등록 정보의 **기본 언어는 영어(미국)**이고, **한국어(`ko-KR`) 문구도 준비되어 있습니다** —
`docs/play-store-listing.md`의 "Korean listing (`ko-KR`)" 절입니다. 두 언어 모두 같은 감사를 거친
같은 내용이며, 조건절("기기가 인코딩할 수 있는 경우", "인코더가 10비트를 지원하는 기기에서는"
등)과 상표 귀속, Android 최소 버전이 그대로 옮겨져 있습니다. **한쪽만 고치지 마세요** — 한 언어가
다른 언어보다 더 많이 약속하는 등록정보는 앱이 하지 않는 일을 약속하는 것과 같은 결함이고,
`tools/check_docs.py`가 양쪽의 글자 수·줄바꿈·Android 최소 버전을 함께 검사합니다.

## 1. 앱 만들기

Play Console → **모든 앱** → **앱 만들기**

- 앱 이름: `TeleCam Pro`
- 기본 언어: **영어(미국)** — 한국어는 아래 3단계에서 번역 언어로 추가합니다.
- 앱 또는 게임: **앱**
- 무료 또는 유료: **무료**
  - 무료로 만든 뒤에는 유료로 바꿀 수 없습니다. 유료 전환 계획이 있다면 여기서 정해야 합니다.

패키지 이름은 이 화면에서 정하지 않습니다. **첫 AAB를 업로드할 때** 번들 안의
`me.hletrd.telecampro`가 그대로 앱의 패키지 이름이 되며, 이후 영구히 바꿀 수 없습니다.

## 2. 앱 설정 (좌측 "앱 설정" 대시보드)

순서대로 처리하면 됩니다. 각 항목의 실제 입력값 출처를 함께 적었습니다.

### 2-1. 앱 액세스 권한
로그인 없이 모든 기능을 쓸 수 있으므로 **모든 기능을 특별한 액세스 권한 없이 사용할 수 있음**을
선택합니다.

### 2-2. 광고
**아니요, 앱에 광고가 없습니다.**

### 2-3. 콘텐츠 등급
설문을 작성합니다. 이 앱은 사용자 생성 콘텐츠를 공유하지 않고, 광고도 데이터 수집도 없으므로
전 연령가로 나옵니다. 설문 답변을 임의로 낙관적으로 채우지 말고 실제 동작대로 답하세요 — 등급
설문의 허위 답변은 정책 위반입니다.

### 2-4. 타겟층 및 콘텐츠
- 타겟 연령: **13세 이상** (아동 대상 아님)
- 아동에게 어필하는 요소 없음
- Play Families 정책 준수 대상: **아니요**

### 2-5. 데이터 보안 (Data Safety)
**출처: `docs/play-data-safety.md`의 "Console Answers" 표.**

핵심 답변은 다음과 같습니다:

| 질문 | 답 |
|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유합니까? | **아니요** |
| 수집되는 데이터가 전송 중 암호화됩니까? | 해당 없음 (수집·전송 자체가 없음) |
| 데이터 삭제 요청 수단을 제공합니까? | 해당 없음 (개발자가 수집하는 데이터 없음. 사용자는 기기 갤러리에서 자신의 사진/영상을 직접 삭제) |
| Play Families 정책 준수? | 아니요 (아동 대상 아님) |
| 광고 포함? | 아니요 |

**데이터 유형은 하나도 선택하지 않습니다.** 카메라 영상과 마이크 입력은 기기 안에서만 쓰이고
개발자에게 전송되지 않습니다. 앱에는 `INTERNET` 권한 자체가 없어 전송할 방법이 없습니다.

### 2-6. 사진 및 동영상 권한 선언
`READ_MEDIA_IMAGES`와 `READ_MEDIA_VIDEO`를 선언하므로 **별도 양식**이 뜹니다. 권한별
250자 사유가 필요하며, **영어 원문을 그대로 붙여넣으세요** —
`docs/play-data-safety.md`의 "Photo and Video Permissions declaration" 절에 두 권한의 사유가
글자 수까지 맞춰 준비돼 있습니다. 임의로 고쳐 쓰면 250자를 넘기거나 앱 동작과 어긋납니다.

**"왜 Android 사진 선택 도구(Photo Picker)를 쓰지 않느냐"고 되물어 올 경우**의 답변도 같은 문서에
있습니다. 요지: 선택 도구는 사용자가 *임의의 파일을 고르는* 용도인데, 이 앱은 고르는 게 아니라
*자신이 저장했던 캡처를 다시 찾는* 것입니다. 재설치하면 Android가 그 파일들의 소유권 기록을
지우기 때문에 생기는 문제이고, 선택 도구로는 "이 앱이 저장한 파일만 보여줘"를 표현할 수 없습니다.

### 2-7. 정부 앱 / 금융 기능 / 건강 앱
모두 **아니요**.

**출처: `docs/play-store-listing.md`.**

| 콘솔 필드 | 영어(기본) | 한국어 |

### 한국어 등록정보 추가하기

**스토어 설정 → 기본 스토어 등록정보** 화면 상단의 언어 선택기에서 **번역 관리 → 자체 번역 추가**
로 `한국어 (대한민국) – ko-KR`을 추가한 뒤, 그 언어 탭에서 위 표의 한국어 문구를 붙여넣습니다.

Play 자동 번역(기계 번역)은 쓰지 마세요. 이 앱의 문구는 "10비트를 지원하는 기기에서는", "지원한다고
알린 렌즈에서" 같은 조건절이 정확성의 핵심인데, 기계 번역이 이런 절을 매끄럽게 지우면 앱이 하지
않는 일을 약속하게 됩니다. 준비된 한국어 문구는 그 조건절을 모두 유지한 채 감수한 것입니다.

### 붙여넣을 때 반드시 지킬 것

**자세한 설명은 코드블록을 그대로, 줄바꿈을 건드리지 말고 붙여넣으세요.** Play는 설명의 줄바꿈을
**있는 그대로** 렌더링합니다. 문서에서 각 문단·글머리표가 한 줄씩 긴 이유가 이것이고, 편집기에서
읽기 좋게 줄을 접은 상태로 붙여넣으면 스토어에 문장 한가운데가 잘린 채로 게시됩니다. 실제로 한 번
그렇게 올라간 적이 있어 `tools/check_docs.py`가 이 형태를 자동으로 검사합니다.

### 그래픽 자산

| 자산 | 규격 | 파일 |
|---|---|---|
| 앱 아이콘 | 512×512 PNG, 알파 포함 | `docs/assets/play/icon-512.png` |
| 그래픽 이미지 | 1024×500 PNG/JPG, **알파 없음** | `docs/assets/play/feature-graphic.png` |
| 휴대전화 스크린샷 | 2장 이상 | `docs/assets/play/screenshots/` (6장) |
| 태블릿 스크린샷 | 7인치 / 10인치 슬롯 | `docs/assets/play/screenshots/tablet/` (4장) |

- **그래픽 이미지에 알파 채널이 있으면 Play가 거부합니다.** 재생성 절차는
  `docs/play-store-listing.md`의 "Required graphic assets"에 있고, 그 안의 변환 스크립트가
  `convert('RGB')`로 알파를 제거합니다.
- 스크린샷은 **세로로 촬영된 것**이어야 합니다. 앱이 중력 방향에 맞춰 글리프를 역회전시키므로
  가로로 들고 찍으면 초점거리 레일이 옆으로 누워 나옵니다.
- 태블릿 스크린샷은 선택이지만, 없으면 태블릿 사용자에게 "이 기기에 맞게 설계되지 않았을 수
  있음" 안내가 뜹니다.
- 현재 태블릿 세트에는 뷰파인더 화면이 빠져 있습니다(피사체 없는 검은 화면이라 제외). 대화면
  추천 노출을 노린다면 실제 피사체를 향한 뷰파인더 캡처를 먼저 채우세요.

## 4. 출시 (내부 테스트 → 프로덕션)

곧바로 프로덕션으로 가지 말고 **내부 테스트**를 먼저 거치세요. 사전 출시 보고서(Pre-launch
report)가 실제 기기에서 앱을 돌려 크래시와 접근성 문제를 잡아 줍니다.

1. **테스트 → 내부 테스트 → 새 버전 만들기**
2. AAB 업로드 (`app/build/outputs/bundle/release/app-release.aab`)
   - Play 앱 서명은 이미 설정되어 있으며, 업로드 인증서는 `9dfdb903…`로 고정입니다. 업로드 후
     콘솔이 표시하는 업로드 인증서 지문이 이 값과 같은지 확인하세요. 다르면 잘못된 키로 서명된
     번들입니다.
3. **출시명(Release name)**: 콘솔이 `1 (1.0)`으로 자동 입력합니다. 그대로 두면 됩니다. 이 값은
   사용자에게 보이지 않는 내부 식별자입니다.
4. **출시 노트**: `docs/play-store-listing.md`의 "Release notes" 코드블록을 `<en-US>` 태그까지
   포함해 그대로 붙여넣고, 이어서 같은 문서 "Korean listing" 절의 출시 노트를 `<ko-KR>` 태그까지
   포함해 붙여넣습니다. 두 언어 블록은 한 입력란에 이어서 넣으며, 태그가 언어를 구분합니다.
   여기도 줄바꿈을 고치지 마세요.
5. 검토 후 **내부 테스트 출시 시작**
6. 사전 출시 보고서 확인 → 문제 없으면 **프로덕션으로 승급**

### 업로드 시 뜨는 경고 두 가지 (둘 다 정상)

- **"난독화 파일(deobfuscation file)이 없습니다"** — 이 빌드는 `isMinifyEnabled = false`라
  난독화를 하지 않습니다. 매핑 파일이 존재하지 않는 것이 정상입니다.
- **"네이티브 코드가 포함되어 있는데 디버그 심볼이 없습니다"** — Compose/미디어 라이브러리가
  가져오는 네이티브 라이브러리이며, 우리가 작성한 네이티브 코드는 없습니다.

둘 다 크래시 리포트의 가독성에 관한 권고이지 출시를 막는 오류가 아닙니다.

### 기기 카탈로그

앱은 특정 모델로 제한되어 있지 않습니다. `minSdk 33`(Android 13) 이상이면 설치됩니다. 다만
**측정된 기기는 네 대뿐**이라는 점을 알고 계셔야 합니다 — 어떤 기기에서 무엇이 확인됐는지는
`docs/play-console-submit.md`의 기기 매트릭스에 있습니다. 그 외 기기는 규격 경로로 동작하도록
설계돼 있으나 실측되지 않았습니다.

## 6. 업로드 직전 최종 점검

```bash
# 1. 트리가 깨끗하고 문서 검사가 통과하는지
git status --porcelain          # 비어 있어야 함
python3 tools/check_docs.py     # 실패 0

# 2. 올릴 번들이 문서가 지목한 그 번들인지
shasum -a 256 app/build/outputs/bundle/release/app-release.aab
```

그리고 `docs/play-console-submit.md`에서 다음 네 가지를 눈으로 확인하세요. 이 문서에 값을
적어두지 않는 이유가 바로 이것입니다 — 그 시트가 유일한 출처입니다.

1. `UPLOAD-READY` 블록의 커밋과 해시
2. 업로드 인증서 지문이 `9dfdb903…`로 그대로인지
3. 패키지된 매니페스트에 `INTERNET`이 없고 `debuggable`이 아닌지
4. 기기 매트릭스에 이번 아티팩트로 측정된 결과가 들어 있는지 (추론이 아니라 실측인지)
